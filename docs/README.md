# 완료 기록 문서

`docs/`는 분석·개선 과정에서 확정된 기준선, 완료 결과, 트러블슈팅처럼 과거 사실을 보존한다.

- 현재 코드의 역할별 설계: [`../doc/README.md`](../doc/README.md)
- 아직 구현하지 않은 작업: [`../roadmap/README.md`](../roadmap/README.md)
- 1·2단계와 M1·M2 개선 기록: [`improvement/README.md`](improvement/README.md)

## 문서 배치 원칙

| 위치 | 내용 | 갱신 방식 |
| --- | --- | --- |
| `doc/` | 현재 코드가 실제로 동작하는 설계 | 코드 변경과 함께 갱신 |
| `docs/` | 완료된 분석·검증·결과·장애 해결 기록 | 사실 오류만 수정하고 당시 판단은 보존 |
| `roadmap/` | 미완료 목표, 우선순위, 완료 조건 | 시작/완료 시 상태와 커밋 갱신 |

새로운 미완료 작업을 `docs/`에 추가하지 않는다. 완료된 roadmap 항목은 상태와 커밋을 roadmap에 기록한 뒤, 필요할 때 별도의 결과 문서를 이 폴더에 추가한다.
